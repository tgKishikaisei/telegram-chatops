# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Нажмите «Report a vulnerability» на вкладке **Security** или напишите мне в Telegram: [@BehruzAvezmatov](https://t.me/BehruzAvezmatov).

## Что сделано

- **Вебхуки.** Алерты принимаются только с верным Bearer-токеном (сравнение за постоянное время, до разбора тела и обращения к БД). Вебхуки GitHub — только с верной подписью `X-Hub-Signature-256` (HMAC-SHA256 тела); `X-GitHub-Delivery` хранится с уникальным ключом, повтор доставки игнорируется. Размер тела ограничен (512 КБ); из алерта читаются только известные поля, строки обрезаются, а мусор вместо JSON даёт 400.
- **Никакого выполнения у себя.** У бота нет shell и нет «выполнить произвольную команду». Действия — только из `bot/content/actions.json`, который проверяется при старте; параметры сверяются с регулярными шаблонами (`;rm` и подобное не пройдёт). Сам каталог меняется только через код-ревью и сборку образа.
- **Правило двух ключей.** Опасное действие подтверждает другой оператор и только в течение заданного времени; сам себе подтвердить нельзя, наблюдатель — не может, повтор и просроченный запрос не сработают.
- **Агент.** Запрос подписан `HMAC(secret, "<ts>.<тело>")`, агент проверяет подпись, возраст запроса (≤ 5 минут) и одноразовость `request_id`. Пример проверки — в README.
- **Роли.** viewer / operator / admin проверяются в сервисах, а не только в кнопках; бот отвечает только участникам команды (кроме `/whoami`); администратор не может понизить самого себя.
- **Устойчивость.** Вебхук только пишет в БД (outbox), пост публикует фоновая задача; флаг «опубликовано» снимается, только если инцидент не менялся после чтения (ревизия). Переходы статусов — атомарными `UPDATE … WHERE`.
- **Аудит.** Каждое действие людей и системы пишется в журнал: кто, что, когда.
- **Вывод.** Строки из алертов и GitHub обрезаются, управляющие символы удаляются, при показе в Telegram — экранируются.
- **Секреты.** В продакшене — Docker secrets (`secrets/<имя>` → `/run/secrets/<имя>`), не переменные окружения. `.env`, `secrets/` и данные исключены из git и из образа. Фильтр логов вырезает значения секретов и строки, похожие на токены.
- **Контейнеры.** Процесс без root, файловая система только для чтения, `cap_drop: ALL`, `no-new-privileges`; PostgreSQL и Redis — во внутренней сети без выхода наружу; у приложения отдельная роль БД без прав на изменение схемы. Наружу смотрит только Caddy с HTTPS.
- **Зависимости.** `requirements.lock` с SHA-256 каждого пакета и установка с `--require-hashes`; GitHub Actions закреплены по SHA коммита.

GitHub Actions на каждый push запускает тесты, проверку миграций, `ruff`, `bandit`, `pip-audit`, сборку образа, `trivy` (уязвимости, конфигурация, секреты) и `zizmor`.

## Что не проверялось

Нагрузочного тестирования и внешнего аудита не было. Приём вебхуков и кнопки проверены тестами и сквозным прогоном с подменённым Telegram, а не на боевых Alertmanager и GitHub.
